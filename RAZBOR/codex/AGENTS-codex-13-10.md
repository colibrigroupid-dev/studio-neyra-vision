# neyra.vision — общий контекст Codex и Claude Code

## Продукт и текущее состояние

- Платформа кинокомпании Казахстана. Языки интерфейса: русский и казахский.
- Путь проекта: сценарий → раскадровка → ИИматик → работа команды над кадрами → постпродакшен.
- Целевой адрес: https://studio.neyra.vision.
- Сейчас создан кликабельный прототип на HTML/CSS/JavaScript без сборщика. Рабочие исходники находятся в `dist/`; эта папка намеренно хранится в репозитории и публикуется целиком.
- Данные сохраняются только в браузере. Сервер, авторизация, настоящие приглашения, совместное редактирование и генерация изображений/видео пока не подключены.
- Публичные обещания и прежние ошибки Neyra — материалы для исследования, а не доказательства возможностей нашего продукта.

## Совместная работа

1. У каждой задачи должны быть результат, область изменения и критерии проверки. У каждой рабочей копии в данный момент один автор изменений.
2. Второй агент получает конкретное задание на независимую проверку. В режиме проверки он читает исходники и отчёт о проверках; не редактирует файлы.
3. Перед передачей автор фиксирует версию или точное состояние изменений, список затронутых файлов, проведённые проверки и ограничения. Результат передаётся через документ или вывод команды.
4. Проверяющий сообщает подтверждённые ошибки: приоритет, файл и строку, сценарий воспроизведения, ожидаемое и фактическое поведение. Предложения по улучшению отмечает отдельно от ошибок.
5. Автор воспроизводит замечания, исправляет подтверждённые проблемы и проверяет результат. Роли Codex и Claude могут меняться между задачами.
6. Для одновременного редактирования используйте отдельные ветки и рабочие копии Git; координатор объединяет изменения после проверки.
7. Проверяйте поведение тестами и в браузере: согласие двух агентов само по себе не доказывает корректность. Не заявляйте о проверках, которые не выполнялись.
8. Не создавайте бесконечные взаимные вызовы. После двух раундов проверки сформулируйте оставшиеся конкретные проблемы или завершите задачу.

## Приоритеты проверки

- Текст автора сохраняется дословно; ИИ предлагает изменения отдельно. Импорт не должен незаметно заменять существующий сценарий.
- Версии сценария восстанавливаются с сохранением текущего черновика.
- Язык интерфейса не меняет язык или текст сценария.
- Изменения сценария сохраняют материалы кадров и отмечают необходимость пересмотра.
- Пользовательский ввод выводится безопасно; имена, сценарий и комментарии не превращаются в HTML.
- Ошибка сохранения не выдаётся за успешное сохранение.
- Демонстрационные функции и локальное сохранение обозначены честно.
- В настоящем командном модуле права должны проверяться сервером, а не только интерфейсом.

## Проверки текущего прототипа

Из корня репозитория:

```sh
node --check dist/app.js
node --check dist/data.js
node --check dist/timeline.js
node verify.mjs
```

По области изменения проверяйте в браузере: русский/казахский, создание проекта, редактирование и восстановление сценария, сохранение после перезагрузки, карточку кадра, ИИматик и управление с клавиатуры. Проверки мобильных размеров ещё не завершены; не представляйте их выполненными.

## Публикация и доступ

- Существующий Sites project_id хранится в `.openai/hosting.json`; используйте его, не создавайте другой сайт.
- Доступ к опубликованному прототипу сейчас частный. Менять аудиторию следует только по прямому запросу пользователя.
- Публикацию выполняет координатор через существующий процесс Sites в рамках задания пользователя.
- Не сохраняйте ключи, токены, пароли или полный вывод авторизации в коде, отчётах и Git.

Следующая предложенная функциональная задача — настоящий модуль проектов и сценария: серверное сохранение, версии, сцены, участники и права доступа. Это направление, а не разрешение начинать весь модуль без задания пользователя.
