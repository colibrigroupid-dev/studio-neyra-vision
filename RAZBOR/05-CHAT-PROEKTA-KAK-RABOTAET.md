# Чат проекта → сайт: как Александр делает это сегодня и что из этого становится платформой

Разобрано 13.10.2026 по живым папкам в `~/Documents/CODE/` (ОРДА, ЖОЛАМА-МАҒАН, ТОҚЫЛДАҚ, TALANT, DAVID-SASUN, KINO-STANCIYA/PROEKTY/er-tostik) и по памяти о проектах.

## 1. Как это устроено сейчас

**Один проект = одна папка = один чат Claude Code в этой папке.** Александр открывает Claude (вкладка Code) в папке проекта и всё делает разговором: концепт, сценарий, разбор, кадры, смета, письма. Claude пишет результат в файлы этой же папки. Чат можно закрыть, папка остаётся, следующая сессия читает её и продолжает.

**Сайт — это сборка из папки.** В папке проекта лежит `site/` или `site-src/` с исходником страницы и скриптом сборки. Скрипт собирает `index.html` и кладёт его в репозиторий сайта (`colibristudio/public/<slug>/` или `neyra-vision/<slug>/`), потом `git push` — и страница живёт по адресу `colibristudio.ai/<slug>/` или `neyra.vision/<slug>/`.

**Замок по коду.** Содержимое страницы шифруется кодом доступа прямо в скрипте сборки (PBKDF2-SHA256 + AES-GCM, 310 000 итераций); в исходнике страницы нет ни текста, ни цифр — только шифр. Два уровня: код команды (ORDA2026, ZHOLAMA2026, общий TAURUSDGTL) открывает разбор и кадры, PRO-код продюсера (ORDAPRO, ZHOLAMAPRO) открывает смету. Это уже и есть «ключи по ролям».

**Разделы страницы** повторяются от проекта к проекту: шапка-тайтл с кадром 16:9 · логлайн и синопсис · герои (портрет + 3 строки) · мир и референсы тона · кадры и тизер · команда (Анна и Анара первыми) · план и смета (по PRO-коду) · контакт продюсера.

**Киностанция** даёт стандартный скелет папки проекта (`PROEKT.md`, `ZHURNAL.md`, `01-zamysel`, `02-scenariy/drafty`, `03-vizual/referensy|kadry`, `04-video/proby|chistovik`, `05-montazh`, `06-zvuk`, `materialy`) и правила: решения живут в файлах, драфты не перезаписываются, журнал в конце сессии. Пример живого проекта — `er-tostik` (12.10): PROEKT.md, ЧИТАТЬ-ПЕРВЫМ.md, синопсис, персонажи, поэпизодник, заключение, архив прежней основы.

## 2. Что в этом сильно и что ломается

Сильно: память проекта в файлах (не в чате); один язык общения — «что у нас по проекту»; страница собирается из тех же файлов, значит не расходится с работой; доступ без аккаунтов — код в ссылке; сборка без сервера, статика на GitHub Pages.

Ломается:
1. **Пять разных сборщиков** — `ОРДА/site/build.py`, `ЖОЛАМА-МАҒАН/site-src/build.py`, `ТОҚЫЛДАҚ/site-src/build.py`, `TALANT/site-src/build.sh`, `DAVID-SASUN/site-src/build.mjs`. Каждый написан заново, у каждого свои поля и свои баги; общий код TAURUSDGTL пришлось прошивать патчем, который теряется при пересборке.
2. **Страница знает только то, что в `site-src/`**, а не то, что в папке проекта: кадры, синопсис, смету копируют руками из `01-zamysel/` и `03-vizual/` в исходник страницы. Расхождение — вопрос времени.
3. **Нет состояния.** На странице не видно, какой этап пройден, какой кадр принят, что ждёт режиссёра. Это живёт в журнале и в голове.
4. **Нет обратной дороги.** Замечание режиссёра к кадру приходит в Telegram, а не на карточку кадра; Александр переносит его в чат руками.
5. **Neyra отдельно.** Сцены, каст, мир, промпты живут в Neyra Studio, страница о них не знает; экспорт — руками через ZIP или Project JSON.

## 3. Что становится платформой (это и есть задачи №06 и №07)

Принцип не меняется: **чат проекта = Claude Code в папке проекта; сайт = сборка из папки.** Меняется то, что ломалось.

| Было | Станет |

| страница из `site-src/` | страница из самих файлов проекта: `PROEKT.md` (шапка, логлайн, статус), `01-zamysel/sinopsis.md`, `personazhi.md`, `03-vizual/kadry/*.jpg` + `kadry/*.md` (карточка кадра), `ZHURNAL.md` (лента), `SMETA.md` (по PRO-коду) |

Что остаётся ручным по правилам: платные генерации (после показа плана), выкат на прод (по слову Александра), казахский текст (вычитка носителем).

## 4. Чем это отличается от демопроекта Codex в `studio/`

Демопроект — интерфейс «всё в браузере»: редактируешь сцены и кадры мышью, данные в localStorage. Путь Александра — «всё в чате, файлы в папке, сайт из папки». Это не конкуренты, а два входа к одной папке: когда у Codex появится сервер (№15), `studio/` будет читать и писать те же файлы проекта, что и чат, а сборщик — публиковать их. Пока сервера нет, источник правды — папка, демопроект — витрина интерфейса.

## 6. Дизайн страницы проекта — направление (по навыку веб-мастера, `kino-platformy.md` и `nishi.md`, 13.10)

**Режим страницы — «показать»**: работа ведёт, интерфейс отступает. Смотрят продюсер, режиссёр, сценарист, копродюсер по коду; за 5 секунд должны понять: что за фильм, на каком этапе, что ждёт их решения. Одно действие — открыть свой раздел.

**Откуда берём форму.** Первый экран — как у страниц тайтлов Netflix / Apple TV / HBO: кадр или петля 16:9 на всю ширину, титульный блок внизу слева поверх градиента в цвет фона, мелкая метка-статус капсом («Полнометражный фильм · раскадровка · веха 2 из 4»), название крупно, строка метаданных через точки (`2027 · 96 мин · 16+ · драма`), логлайн в 1–2 строки, две кнопки (главная заливкой — «Смотреть тизер» или «Открыть кадры», вторая прозрачная — «Карта проекта»), строка «Режиссёр … · Продюсеры Анна Чакиртова, Анара Жунусова». Дальше — порядок секций тайтла: ролики лентой 16:9 с длительностью в углу → сцены списком (номер, слаглайн, 1–2 строки, хронометраж, кадр) → карта проекта `<dl>` (режиссёр, сценарист, продюсеры, статус, хронометраж, язык, бюджет по PRO-коду) → герои (портреты 16:9 с воздухом, «актёр — роль») → раскадровка и карточки кадров → сценарий отрывком «американкой» + PDF по коду → команда титрами «роль — имя» по шаблону кредитов → журнал → контакт продюсера.

**Палитра — из кадров фильма.** Как у NEON: у каждого проекта свой фон и акцент, снятые пипеткой с ключевого кадра (`--bg`, `--accent` в `PROEKT.md`); текст тёплый белый, зерно 3–6 %. Общее для всех проектов — только сетка и типографика, цвет у каждого свой. Так страницы узнаются, а не штампуются.

**Типографика.** Название фильма — узкий плакатный капс с разрядкой, как финальные титры; для казахских названий (Ә Ғ Қ Ң Ө Ұ Ү Һ І) — Geologica 600 или Noto Serif Display, Sofia Sans Extra Condensed не берём. Текст — Onest 16–19 px. Подписи — PT Mono / JetBrains Mono капсом: `ОБЩИЙ · ДРОН, ОБЛЁТ · 24 ММ · 6 С`, таймкоды, номера кадров `12.1`. Сценарий — PT Mono «американкой» на `ch`-отступах, светлый лист на тёмной странице.

**Подпись страницы (одна).** Лента карточек кадров со статусами: красный / жёлтый / зелёный в углу кадра, замечание режиссёра под спецификацией. Это та единственная вещь, которой нет ни у платформ, ни у дистрибьюторов, и которая показывает, что фильм делается здесь и сейчас. Остальное тихое.

**Движение.** Одно: кадр первого экрана медленно дышит (scale 1.08 → 1.0 за 6–8 с), остальное — переходы 150–300 мс; `prefers-reduced-motion` гасит всё.

**Чего не делать.** Три одинаковые карточки, иконки вместо кадров, плашки над каждым заголовком, градиентный текст, чистый `#000`, постерная плитка 2:3, названия моделей, цифры и имена, которых нет в папке.

**Печать.** `@media print`: раскадровка в две колонки на белом, hero и ленты скрыты — страницу можно отдать как PDF на встречу.

**Как это проверяется.** По `PROVERKA.md` плюс чек-лист веб-мастера `priyomka.md`: пять секунд, 375 px, худшие данные (длинное имя, пустое поле «нет фото»), казахские буквы, консоль. Первый проект для сборки — «Ер Төстік»: есть синопсис, персонажи, поэпизодник, кадры героев.
