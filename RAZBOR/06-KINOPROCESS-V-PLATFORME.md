## 1. Классический процесс и кто за что отвечает

| Стадия | Что происходит в обычном кино | Документы и артефакты | Роли (кто модератор раздела) |
|---|---|---|---|
| **1. Девелопмент** | идея → права → сценарий → пакет для денег | логлайн, заявка, синопсис, тритмент, поэпизодник, драфты сценария, читательские заключения, библия (для сериала), питч-дек, опционное соглашение | продюсер (владелец проекта), сценарист, скрипт-редактор |
| **2. Препродакшн** | разбивка сценария → кастинг → локации → визуальная разработка → раскадровка → план и смета | **разбивка сценария (breakdown)**: сцены, персонажи, локации, реквизит, костюм, грим, транспорт, животные, VFX; кастинг-листы и пробы; локейшн-скаутинг и фото локаций; лукбук/мудборд, эскизы, концепты героев и мест; раскадровка, шот-лист, превиз/аниматик; календарно-постановочный план, смета, договоры | режиссёр, второй режиссёр, кастинг-директор, локейшн-менеджер, художник-постановщик, художник по костюмам, оператор-постановщик, линейный продюсер |
| **3. Продакшн (съёмка)** | смена за сменой по вызывным листам | вызывные листы, отчёты смены, скрипт-репорты (непрерывность), дейлис, лог дублей, DIT-отчёты | второй режиссёр, скрипт-супервайзер, оператор, звукорежиссёр площадки, DIT |
| **4. Пост** | монтаж → звук → музыка → VFX → цвет → мастер | монтажные версии (assembly, rough cut, fine cut, picture lock), EDL, список VFX-шотов, спот-лист звука и музыки, сведение, DCP/мастер | монтажёр, звукорежиссёр, композитор, VFX-супервайзер, колорист |
| **5. Выпуск** | фестивали, прокат, платформы, промо | тизер, трейлер, постер, пресс-кит, DCP, субтитры, дубляж, отчёты | продюсер, маркетинг |

Сквозные роли: **продюсер** (видит всё, принимает вехи, смету), **режиссёр** (творческие решения, статусы кадров), **скрипт-супервайзер** (непрерывность: кто во что одет, что в руках, время суток — в нашем случае это замки внешности и мира).

## 2. Как это ложится в платформу: одно окно проекта

Окно проекта = `studio/` (рабочее пространство) + страница проекта `p/<slug>/` (витрина состояния) + чат проекта (Claude Code для Александра). Все три читают и пишут одни и те же данные (сервер №15: проекты, версии, сцены, кадры, участники). Разделы окна повторяют стадии кино, названия — киношные, не айтишные:

| Раздел окна | Что в нём | Чем делается у нас | Кто модератор |
|---|---|---|---|
| **Обзор** | логлайн, статус, этап и вехи, кто в команде, что ждёт решения | агрегат остальных разделов | продюсер |
| **Сценарий** | драфты с версиями, читательские заключения, поэпизодник, библия | `scenariy/` (Fountain, ассистент NEYRA) + навык `scenarist` в чате | сценарист, скрипт-редактор |
| **Разбивка** (breakdown) | из сценария автоматически: список сцен (ИНТ/НАТ, локация, время, страницы), персонажи по сценам, локации, реквизит, костюм, спецэффекты, животные, транспорт; «что нужно для сцены» | парсер Fountain → сущности; в Neyra — `import_screenplay` + Script Breakdown (слаглайны, дедупликация локаций, WorldEntity) | второй режиссёр, скрипт-супервайзер |
| **Герои** (кастинг) | карточка героя: описание, возраст, арка, **портрет-эталон и замок внешности**, голос, листы ракурсов и эмоций, костюм по сценам; «виртуальный кастинг» — варианты портрета, выбор одного ⭐ | Nano Banana (портрет и листы), Neyra `update_character` / Lock Appearance, Seedance Trusted Avatar для видео | режиссёр, кастинг-директор, художник по костюмам |
| **Локации** (скаутинг) | карточка локации: ИНТ/НАТ, описание 8–20 слов «что никогда не меняется», время суток и свет, мастер-пластина и ракурсы, план площадки 10×10, в каких сценах | Nano Banana (пластины), Neyra `upsert_world_entity` (location) + 3D-стенд для блокинга | локейшн-менеджер, художник-постановщик |
| **Мир** (арт-отдел) | реквизит, костюмы, транспорт, атмосферы, палитра, лукбук, референсы тона | Nano Banana, `upsert_world_entity` (prop/wardrobe/vehicle/atmosphere) | художник-постановщик, художник по костюмам |
| **Раскадровка** | кадр на сцену, шот-лист (крупность, движение, объектив, длительность), аниматик | Nano Banana по карточкам сцен с @героями и локацией; аниматик — склейка кадров по длительности (`montazh`) | режиссёр, оператор-постановщик |
| **Кадры** (производство) | карточка каждого кадра: промпт, варианты, выбранный ⭐, статус 🔴🟡🟢, замечания режиссёра, кто принял; видео из принятого кадра | Nano Banana → Seedance 2.5 (по утверждённым кадрам), 3D-стенд Neyra для сложных мизансцен | режиссёр, оператор, VFX-супервайзер |
| **Непрерывность** | сводка по героям и локациям: что в кадре 12.3 не совпадает с 12.1 (одежда, свет, реквизит) | автоматическая проверка по замкам; в Neyra — Continuity Supervisor | скрипт-супервайзер |
| **Звук** | реплики (голоса героев), шумы, атмосфера, музыка, спот-лист | навык `zvuk`, Seed Audio/ElevenLabs по голосу героя | звукорежиссёр, композитор |
| **Монтаж и мастер** | сборки (черновая → чистовая → lock), EDL, цвет, мастер, тизер | `montazh` (ffmpeg), экспорт EDL из Neyra | монтажёр, колорист |
| **План и смета** | календарный план по этапам, вехи, расход кредитов и денег, договоры | таблица в проекте; по PRO-коду/роли продюсера | продюсер, линейный продюсер |
| **Журнал** | что решили, когда, кто | `ZHURNAL.md` ↔ журнал сервера | все пишут, продюсер модерирует |

Правило наименований: в интерфейсе — «Разбивка», «Кастинг», «Локации», «Раскадровка», «Дейлис», «Непрерывность», а не «entities», «assets», «pipeline».

## 3. Из сценария → локации и аватары (ключевая автоматика)

1. **Разбивка**: из драфта `.fountain` парсер строит: сцены (номер, ИНТ/НАТ, локация, время суток, страницы, действующие лица, реквизит из действия по словарю, спецметки `[[VFX]]`), персонажей (по именам реплик и первому появлению КАПСОМ), локации (по слаглайнам, с дедупликацией «кухня» = «кухня Айнур»). Результат — файлы `01-zamysel/razbivka.json` + таблица в `02-scenariy/razbivka.md`; в Neyra — те же сущности через MCP.
2. **Карточки героев и локаций создаются автоматически пустыми**, с тем, что известно из сценария (возраст, описание из действия, в каких сценах, с кем). Дальше человек (или Claude в чате) дописывает «что никогда не меняется» — 8–20 слов для локации, 25–60 слов для героя.
3. **Генерация референсов — только после «да»**: платформа собирает промпт по мастер-промпту (Nano Banana), показывает список кадров к генерации и стоимость; режиссёр жмёт «генерить». Для героя: 3–6 вариантов портрета → выбор одного ⭐ → замок внешности → листы ракурсов/эмоций. Для локации: мастер-пластина → ракурсы день/ночь.
4. **Замок** = выбранный портрет + текст внешности, которые дословно идут в каждый промпт кадра, где есть этот герой (`@Имя`), и в Seedance как референс. Это и есть «аватар».
5. Всё, что сгенерировано, ложится в папку проекта (`03-vizual/geroi/<imya>/`, `03-vizual/lokacii/<imya>/`) и на сервер — страница проекта и окно показывают одно и то же.

## 4. Команда и доступы по e-mail

## 3а. Герои и локации отдельно от сценария — как сделать удобно (установка 13.10 01:13)

Герой и локация — самостоятельные сущности **библиотеки студии**, а не только производные сценария. Их можно завести до сценария, между проектами, и подключать к любому проекту (как в Neyra Characters: герой живёт в библиотеке, в фильм попадает через «Cast → Library»).

**Четыре входа, один результат — паспорт.**
1. *Из сценария* — разбивка создаёт карточку с тем, что известно (§3).
2. *С нуля* — одна форма из трёх полей: имя · «кто это / что это» одним предложением · референсы (0–5 фото, перетащить). Всё остальное платформа предлагает сама.
3. *По фото* — реальный актёр или реальное место: загрузил фото → карточка; для реального человека обязательна галочка согласия (как Likeness consent в Neyra) и фото без ретуши, 5 ракурсов отдельными файлами (правило из памяти «референсы под видео»).
4. *Из библиотеки* — «добавить в проект» героя или локацию, уже сделанных в другом проекте студии.

**Паспорт героя** (одна карточка, читается киношником за 10 секунд): портрет-эталон ⭐ · имя и роль · возраст · «что никогда не меняется» (25–60 слов, пишет платформа, правит человек) · листы: ракурсы, эмоции, возрасты · костюм по сценам · голос (образец 20–30 с) · в каких проектах и сценах · статус: черновик → утверждён (замок). **Паспорт локации**: мастер-пластина ⭐ · ИНТ/НАТ · «что никогда не меняется» (8–20 слов) · свет по времени суток (утро/день/вечер/ночь — четыре пластины) · план площадки · суб-локации · в каких сценах · статус.

**Удобство — семь правил.**
- Человек никогда не видит промпта, если не хочет: кнопка «Показать, что уйдёт в генерацию» — для режиссёра и оператора; остальным — «Сделать 4 варианта», «Ещё 4», «Выбрать этот».
- Выбор, а не настройка: варианты показываются сеткой 2×2, один клик ⭐ — и это замок. Переделать можно, но старый замок остаётся в истории.
- Цена до нажатия: «4 портрета · ≈ 0,20 $ · ключ студии», и ничего не списывается без «да». Платные действия — только с ролью режиссёра/продюсера/художника.
- Один стиль на проект: проект держит «стиль мира» (3 кадра-референса + палитра, как Style DNA в Neyra); все герои и локации проекта генерятся в нём — так они «дружат» в одном кадре. При добавлении героя из библиотеки в другой проект платформа предупреждает, что стиль разный, и предлагает перерисовать листы.
- Герой в кадре = `@Имя`: в раскадровке и кадрах режиссёр пишет «@Ерке идёт к коню», и замок подставляется сам (как в Neyra). Локация = `#Аул`.
- История, не перезапись: каждый вариант, замок и правка — версия с датой и автором; «вернуть вчерашний портрет» одним кликом.
- Непрерывность видна сразу: в паспорте счётчик «в 14 кадрах · 2 расхождения» и ссылка на них (№22).

**Где это живёт.** В папке — `03-vizual/geroi/<imya>/` и `03-vizual/lokacii/<imya>/` (паспорт `KARTOCHKA.md` + файлы) внутри проекта, библиотека студии — `BIBLIOTEKA/geroi/`, `BIBLIOTEKA/lokacii/` в Киностанции; на сервере — те же сущности с полем `projects[]`. В Neyra — `update_character` / `upsert_world_entity` + Lock Appearance; в видео — Seedance с референсом замка (Trusted Avatar для реальных лиц).

## 6. Дата-рум проекта: всё собирается, всё выгружается, видно, как создавалось (установка 13.10 01:20)

Цель: студия может **продать проект или выгрузить его целиком**, и покупатель видит не только результат, но и как он создавался — кто, когда, чем, на каких правах. Это то, что у Neyra называется Data Room + IP Passport, у нас — **дата-рум проекта (ДРК)**.

**Что лежит в ДРК** (автоматически, без ручной сборки):
1. Документы разработки — все версии сценария, заключения, синопсис, библия, поэпизодник, разбивка.
2. Герои, локации, мир — паспорта с замками, листы, согласия на реальные лица.
3. Раскадровка, кадры, аниматик, тизер, видео — принятые ⭐ и история вариантов.
4. Звук, монтаж, мастер.
5. План, смета, договоры, права.
6. **Журнал происхождения** (provenance): к каждому созданному файлу — кто запросил, когда, какой инструмент и модель (внутри студии — точное имя, наружу — «технология NEYRA»), промпт и параметры, стоимость, кто принял и когда. Для текстов — версии с автором и датой. Журнал только дописывается (append-only), у каждой записи хэш файла, чтобы подмену было видно.
7. **Цепочка прав** (chain of title): авторы и их согласия, лицензии использованных моделей (Z-Image Turbo и LoRA — Apache 2.0; Nano Banana, Seedance — по условиям провайдера, храним дату и версию условий), права на музыку и голоса, согласия на лица, договоры команды. Без этого проект не продать.

**Как это делается у нас:** каждый сгенерированный файл кладётся с соседним `*.json` (происхождение) — это умеют делать `tools/raskadrovka.py`, навыки Nano Banana/Seedance и MCP-мост Neyra (`get_audit_log`); сервер №15 ведёт журнал операций; `ZHURNAL.md` остаётся человеческим журналом решений. **Выгрузка** — `tools/export-project.py <slug>`: ZIP с понятной структурой папок по стадиям, `MANIFEST.json` (список файлов, хэши, происхождение, права), `PASPORT-PROEKTA.pdf` (на двух языках: что это, статус, команда, права, что внутри) и `ЖУРНАЛ.pdf`. Такой же ZIP — кнопка «Выгрузить проект» в окне проекта (роль продюсера) и в Neyra-стиле Data Room «Download ZIP».

**Готов к продаже — чек-лист в обзоре проекта:** права на сценарий подтверждены · согласия на лица есть · лицензии моделей записаны · все принятые кадры имеют происхождение · смета и план актуальны · журнал без разрывов. Пока хоть один пункт красный, кнопка «Пакет для покупателя» не активна.

**Личное и внешнее:** внутри ДРК хранятся точные имена моделей и промпты (это и есть ценность для покупателя-студии), наружу на сайт идёт только «технология NEYRA» — правило остаётся.

## 7. Карта производства: вагончики параллельно, апрувы по шагам, всем видно (установка 13.10 01:25)

Каждый работает над своей задачей, а весь процесс виден одной картиной. Картина — **карта производства**: сетка «сцены × этапы».

```
                 Сценарий  Разбивка  Герои  Локации  Раскадровка  Кадры  Видео  Звук  Монтаж
Сцена 01  аул      ✓ ◆        ✓        ✓      ✓         ✓ ◆        ●      ○      ○      ○
Сцена 02  побег    ✓ ◆        ✓        ✓      ●         ○          ○      ○      ○      ○
Сцена 03  степь    ✓ ◆        ●        ○      ○         ○          ○      ○      ○      ○
Тизер              ✓ ◆        ✓        ✓      ✓         ✓ ◆        ✓ ◆    ●      ○      ○
```

`○` не начато · `●` в работе (кто) · `✓` готово · `◆` апрув стоит/получен · красная клетка — вернули на доработку.

**Вагончики едут параллельно.** Строка — сцена (или тизер, или серия), столбец — этап. Сценарист доводит сцену 03, художник делает героев сцены 02, оператор раскадровывает сцену 01, звук уже пишет атмосферу тизера. **Апрувы по шагам.** У каждой клетки свой утверждающий: сценарий — продюсер (и автор), разбивка — второй режиссёр, герои и локации — режиссёр, раскадровка — режиссёр с оператором, кадры — режиссёр, звук — режиссёр, монтаж — продюсер с режиссёром. Апрув — это запись: кто, когда, что именно (версия/вариант), комментарий. Один клик «принять» или «вернуть» с замечанием одной строкой; вернули — клетка красная, у исполнителя в его списке «вернули: 12.3 — свет не совпадает с 12.1».
