# studio.neyra.vision · правила совместной работы агентов

Этот файл читают все, кто работает в репозитории: Claude Code, Codex и их субагенты. Владелец проекта — Александр. Он ставит задачи, принимает результат и решает споры.

## 1. Одна правда — репозиторий

- Всё, что сделано или решено, живёт в файлах этой папки и в git. Чат любого агента — не память проекта.
- Доска задач — `ZADACHI.md`. Журнал — `ZHURNAL.md`. Чек-лист приёмки — `PROVERKA.md`. Разбор и концепт — `RAZBOR/`.
- Каждая сессия начинается с чтения `ZADACHI.md` и последней записи `ZHURNAL.md`, заканчивается записью в журнал и обновлением доски.

## 2. Два партнёра, две зоны, перекрёстная проверка

| Зона | Владелец | Проверяет |
|---|---|---|
| `index.html`, `assets/` — витрина (главная RU/KZ) | Claude | Codex |
| `studio/` — рабочее пространство проекта (обзор, сценарий, раскадровка, ИИматик, команда, пост) и серверное хранение (проекты, версии, ключи ролей) | Codex | Claude |
| `scenariy/` — редактор сценария (Fountain) с ассистентом NEYRA | Claude (сессия «Сценарий») | Codex |
| `RAZBOR/`, связь с Neyra через MCP, память о платформе Neyra | Claude | Codex |
| `p/` — страницы проектов по ключу (шаблон + сборщик) | Claude | Codex |

Правила зон:
- В чужую зону не пишут. Нужна правка — задача на доске для владельца или замечание в проверке.
- Общие файлы (`AGENTS.md`, `ZADACHI.md`, `ZHURNAL.md`, `PROVERKA.md`, `README.md`) правят оба, только добавлением строк.
- Готово ≠ принято. Статус «проверено» ставит только не-владелец, «принято» — Александр.

## 3. Как берётся и сдаётся задача

1. Задача появляется на доске с номером, владельцем, проверяющим и критерием готовности (что должно быть видно и как проверить).
2. Взял — отметил на доске «в работе» и дату. Одна задача — один агент. Если задача делится, владелец заводит подзадачи `NN.a`, `NN.b` и может отдать их своим субагентам; за результат субагентов отвечает владелец, на доску они не выходят.
3. Сделал — проверил сам по `PROVERKA.md`, записал на доске «готово» и где смотреть (файл, адрес, команда запуска).
4. Партнёр проверяет по `PROVERKA.md` и пишет `proverki/NN-<кратко>.md`: что проверял, чем, что нашёл, вердикт «принять / доработать». Нашёл дефект — не чинит сам, возвращает владельцу с точным описанием.
5. Спор решает Александр. Пока не решил — делается вариант владельца, спор записан на доске.
6. Не больше двух раундов «доработать → проверить» на задачу. После второго — оставшиеся дефекты списком на доску, решает Александр. Согласие двух агентов не доказывает корректность: проверяется запуском и браузером, о невыполненных проверках не заявлять.
7. Материалы Codex (разбор референса, прежние проверки до 08.10, границы и сдача прототипа, его версия правил) лежат в `RAZBOR/codex/`. Это исследование, а не доказательство возможностей нашего продукта.

## 4. Работа в git

- Ветка на задачу: `NN-kratko` латиницей. В `main` — только принятое.
- Коммит с номером задачи в начале: `NN: что сделано`. Перед коммитом — чек-лист.
- Каждый выкат на прод — номер в `version.txt` и тег. На прод — только по слову Александра.

## 4а. Три установки Александра на платформу (13.10.2026 01:07)

1. **Платформа такая, что Александр работает в ней через Claude Code.** Чат проекта — это и есть рабочее место; всё, что он говорит в чате, становится файлами проекта и видно на странице проекта. Интерфейсы (`studio/`, `scenariy/`) — второй вход к тем же файлам, не замена чата.
2. **Порядок: сначала сценарий.** Пока блок сценария не работает для сценаристов хотя бы базово, вверх не идём. Потом картинки и видео, и генерим их **только через Nano Banana и Seedance** (ключи Александра, мастер-промпт из памяти; Higgsfield — как окно к тем же моделям, когда нет своих ключей).
3. **Сначала пользуемся сами, потом продаём студиям.** Значит: никаких решений «для демо», всё должно выдерживать наш собственный проект («Ер Төстік», «Орда»); но с первого дня — без привязки к нашим папкам и ключам (конфиг, slug, ключи ролей), чтобы вторая студия ставила это себе.

4. **Кинопроцесс целиком и по-киношному.** Всё, что есть в классическом производстве (девелопмент → разбивка → кастинг → локации → раскадровка → съёмка/кадры → пост → выпуск), должно быть в окне проекта под киношными именами, чтобы киношники были модераторами разделов. Из сценария автоматически создаются сцены, герои (аватары с замком внешности) и локации. Карта — `RAZBOR/06-KINOPROCESS-V-PLATFORME.md`.
5. **Одно окно проекта, команда по e-mail.** У каждого проекта одно окно (`studio/` ↔ страница ↔ чат), участники входят по почте с ролями и разделами; Александр работает через Claude, остальные — прямо на платформе.

## 5. Правила проекта, которые сильнее вкуса

- Публично — **Neyra Vision** и «технология NEYRA». Neyra Labs не показываем, названия моделей не пишем.
- Русский и казахский. Казахский текст — на шрифтах с буквами Ә Ғ Қ Ң Ө Ұ Ү Һ І (Onest, Geologica, Golos Text, Noto, PT Serif, Cormorant Garamond). Manrope, Unbounded, Sofia Sans — нельзя. Казахские тексты до выкладки вычитывает носитель.
- Кадры 16:9. Цифры, имена, цены, сроки — только настоящие; чего нет — не придумывать, ставить задачу на доску «решение Александра».
- Страницы для команды — только результат, без «откуда взято». Красный не фоном.
- Имена файлов латиницей, без пробелов. Внутри — по-русски.
- Платные генерации (картинки, видео, кредиты Neyra) — только после показа плана Александру.

## 6. Что умеет каждый — чтобы не дублировать

- Claude Code: MCP-мост Neyra (чтение проектов, сцен, каста, мира; запись промптов), память о платформе, навык веб-мастера, Киностанция, субагенты на параллельные задачи.
- Codex: кликабельные прототипы интерфейса, сервер блока «Сценарий», проверка кода и вёрстки.
- Оба: читают и пишут файлы репозитория, запускают локальный сервер (`python3 -m http.server`, порт из `README.md`), снимают экраны на 1440 и 375 px.

## 7. Кто координирует (решение Александра 13.10.2026 00:38)

Александр ставит задачи и принимает результат **в чате Claude Code**. Claude — координатор: ведёт доску, делает свою зону, задачи зоны Codex передаёт Codex через `tools/partner.sh` (`codex exec`), читает его результат, запускает перекрёстные проверки и докладывает Александру одним отчётом. Окно Codex в ChatGPT Александру открывать не нужно; если он всё же даёт задание там, Codex обязан работать в этой папке по этим правилам.

Ограничения `codex exec`: каждая сессия Codex начинается с нуля (контекст — только файлы репозитория, поэтому доска и журнал обязательны); сетевые адреса и браузер в песочнице закрыты — проверки в браузере на 1440 и 375 делает Claude, Codex проверяет код, тесты (`node --check`, `verify.mjs`) и тексты; пишет Codex только в своей зоне и в `proverki/`.

## 8. Вызов партнёра без диалога

Оба агента стоят на этом маке и вызываются из командной строки, поэтому проверку партнёра можно запускать прямо из своей сессии — `tools/partner.sh`:

- `tools/partner.sh proverka 01 codex` — Codex проверяет задачу №01 по `PROVERKA.md` и пишет `proverki/01-codex.md`.
- `tools/partner.sh proverka 02 claude` — то же силами Claude (`claude -p`).
- `tools/partner.sh codex-ro "вопрос"` — спросить Codex, ничего не меняя.

Правила вызова: партнёр в таком режиме пишет только в `proverki/` и не трогает зоны; результат вызова всё равно читает вызвавший и выносит на доску; платные генерации из таких вызовов не запускаются. Проверено 13.10.2026: Codex (`codex exec`, версия 0.162) читает доску из этой папки и правильно называет свою зону и первую задачу.
