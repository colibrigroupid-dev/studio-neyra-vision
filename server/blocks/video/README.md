# Блок «Видео» · контракт №69 для Claude

`from blocks import video` при запуске из `server/`.
Адаптер на стандартной библиотеке Python; маршрутов, фоновой очереди, хранения
проекта, проверки прав, списания и утверждения дубля здесь нет.

## Функции

| Вызов | Результат и граница |
|---|---|
| `prompt(shot, scene, refs_roles, dialogue='', sfx='')` | Строка: роли изображений, действие, сцена, камера, диалог и шумы, запрет музыки, 16:9. Без внешних запросов. |
| `payload(text, refs, duration=5, resolution='720p', first_frame=None)` | Новое тело запроса с фиксированными моделью, 16:9, `generate_audio=True`, `watermark=False`. Без внешних запросов. |
| `api_key()` | `ARK_API_KEY`, иначе содержимое `~/.config/neyra-studio/ark-key`, иначе `''`. Ключи не хранить в проекте, не возвращать клиенту. |
| `create(body)` | `task_id`: один POST, таймаут 60 секунд, без автоматических повторов. Передавать результат `payload()`. Это платное действие вне пробного режима. |
| `status(task_id)` | Один GET, таймаут 60 секунд; `{state, video_url, error, usage}`. Очередью и периодом опроса управляет ядро. |
| `usd(seconds, resolution)` | Число USD: оценка себестоимости без наценки платформы и списания. Неотрицательные конечные секунды, включая дробные. |
| `download(url, path)` | Скачивает в `Path`, возвращает этот `Path`; таймаут 120 секунд, HTTPS, Content-Type `video/*`. Запись потоком во временный файл рядом с итоговым, атомарная замена после полного скачивания. Каталог должен существовать. |

`VideoError.status`, `.code`, `.message` совместимы со стилем блока картинок.
Некорректные входы: `422 / VALIDATION`; отсутствие ключа при реальном вызове:
`503 / VIDEO_KEY_MISSING`; HTTP, транспорт, некорректный ответ или скачивание:
`502 / VIDEO_UPSTREAM`. Ошибка самой генерации возвращается в `status()` как
`state='failed'` и объект `error`, а не как исключение транспорта.

## Исходники промпта

`shot` и `scene` — словари со строковыми полями, уже нормализованные ядром.
Объекты переводов `{ru, kk}` предварительно преобразовать в выбранный текст.
Авторские требования сохраняются в исходном языке; блок их не переписывает.

- Действие: первое непустое `shot.action`, `shot.description`, `shot.prompt`.
  Без действия — ошибка валидации. Если `shot.prompt` отличается от действия,
  он отдельно добавляется как визуальный замысел Director.
- Сцена: `title`, `location`, `time`, `ton`, `vizual`; пустые поля пропускаются.
- Камера: `shot.size` (или `shot.shotSize`), `shot.angle`, `shot.movement`,
  `shot.lens`. Допустима вложенная `shot.camera={size, angle, movement}`;
  верхние поля имеют приоритет. Крупность и ракурс — новый входной контракт,
  существующая схема кадра пока содержит только `lens` и `movement`.
  Отсутствующие параметры не придумываются.
- Статика (`Статичный кадр`, `Статика`, `Қозғалыссыз`, `static`, `fixed`,
  `stationary`, `locked-off`) задаётся текстом
  `locked-off camera, do not change the camera position or the framing`.
  **`camera_fixed` не передаётся**, включая i2v.
- `dialogue` — дословная строка реплики; язык обязателен в
  `shot.dialogueLanguage`, `scene.dialogueLanguage` либо `scene.language`
  (в таком порядке). Другой вариант —
  `{text, language, speaker?, delivery?}` для явного языка, говорящего и подачи.
  Перед репликой указан язык, сама реплика заключена в `{…}`.
  Пустая строка означает отсутствие диалога. Язык не угадывается.
- `sfx` — строка шумов без внешних скобок, помещается в `<…>`.
  Завершающая инструкция всегда:
  `no music, only synchronized sound effects and dialogue`.

`refs_roles` — список в **точном порядке всех изображений** в `content`:
строки вроде `герой Ер Төстік: внешность и одежда` или объекты
`{role: 'character'|'location'|'first_frame', name: '…'}`.
Для героя/локации `name` обязателен. Объект `first_frame` допускается только
первым, `name` у него необязателен. Объекты добавляют ограничения:
герой задаёт внешность, но не фон; локация задаёт планировку и свет, но не людей;
первый кадр задаёт исходную композицию. Роль каждого `@ImageN` объясняется
сразу при первом упоминании, до действия кадра. Упоминание номера без
приложенного референса вызывает ошибку валидации.

## Payload и порядок изображений

`refs` — список строк: HTTPS URL или непустой валидный
`data:image/png;base64,…`. Локальные пути, `http://`, `file://`, `asset://`
не принимаются. Ядро читает утверждённые файлы проекта и при необходимости
кодирует их в data URL; содержимое файла не попадает в журнал проекта.

Длительность — целое число **4–15 секунд** (bool/дробь отклоняются).
Разрешение — **480p / 720p / 1080p**. Не более **6 изображений суммарно**,
включая первый кадр. Лишние изображения отклоняются, не обрезаются.

`content[0]` — `{type: 'text', text: …}`. Если есть `first_frame`, следом идёт
`{type: 'image_url', image_url: {url: …}, role: 'first_frame'}`;
остальные изображения имеют `role: 'reference_image'`.
Первый кадр — `@Image1`, остальные референсы — начиная с `@Image2`.
Без первого кадра первый референс — `@Image1`.
Ядро обязано собрать `refs_roles` в том же порядке: блок не связывает два
независимых вызова `prompt()` и `payload()`.

```python
from blocks import video

# shot, scene и ссылки заранее получены из утверждённых данных проекта.
roles = [{"role": "first_frame"}]
roles += [{"role": "character", "name": character["name"]}]
text = video.prompt(shot, scene, roles,
                    dialogue={"text": reply, "language": dialogue_language},
                    sfx=shot_sfx)
body = video.payload(text, [character_data_url],
                     duration=5, resolution="720p", first_frame=shot_data_url)
estimate = video.usd(body["duration"], body["resolution"])
# Сохранить план, показать цену, дождаться явного запуска пользователя.
# task_id = video.create(body)
# result = video.status(task_id)
```

## API, состояния и пробный режим

`https://ark.ap-southeast.bytepluses.com/api/v3`,
`POST /contents/generations/tasks`, `GET /contents/generations/tasks/<id>`;
серверная модель `dreamina-seedance-2-5-260628`.
API сверено с рабочим `welluma-art/seedance.py` и памятью флота;
реального вызова в задаче №69 нет. Это внутренние параметры адаптера;
название модели не выводить в публичный интерфейс.

Состояния BytePlus `queued`, `running`, `succeeded`, `failed`, `cancelled`
возвращаются без изменения. `expired` преобразуется в `failed`; если провайдер
не прислал ошибку, добавляется `{code: 'VIDEO_EXPIRED', message: '…'}`.
Неизвестный статус или успех без адреса видео — ошибка внешнего API.
`video_url` читается из `content.video_url`, `error` и `usage` сохраняются
объектами без пересчёта. Отмена здесь не реализована: возвращаемый
`cancelled` не означает наличия маршрута отмены.
Официальные описания:
[создание задачи](https://docs.byteplus.com/en/docs/modelark/create-video-generation-task-api),
[получение задачи](https://docs.byteplus.com/en/docs/modelark/get-video-generation-task-api).
У BytePlus URL видео действует 24 часа; ядру нужно забрать файл при успехе,
не использовать этот URL как постоянный файл дубля.

При `NEYRA_ASSISTANT_FAKE=1` ключ и сеть не используются:
`create()` возвращает `fake-<hex>`, `status()` сразу возвращает
`{state: 'succeeded', video_url: None, error: None, usage: {}, fake: True}`.
Идентификаторы `fake-<hex>` распознаются и после выключения переменной.
Это проверка проводки, видеофайла нет. Не вызывать `download(None, …)`,
не списывать деньги/токены, не утверждать такой ответ как настоящий дубль.

## Что подключить в маршрутах и хранить в проекте

1. Подготовка: проверить права Production, принадлежность проекту и актуальные
   утверждения сцены, образов и кадра; собрать снимок версий, референсы,
   `prompt()` → `payload()` → `usd()`. Показать параметры и цену.
   Передача Writer → Art → Director сама по себе не вызывает `create()`.
2. Явный запуск: записать job с ULID и `studio_id`, резервированием стоимости
   и ключом повторного запроса; затем один `create(body)` и сохранить `taskId`.
   После таймаута результат POST может быть неизвестен: зафиксировать ошибку
   и не отправлять новый платный POST незаметно. Возобновление обычного опроса
   выполняется по сохранённому `taskId` через `status()`, не через `create()`.
3. Опрос: найти job **по проектному id**, проверить право, вызвать
   `status(job.taskId)`, сохранить состояние, ошибку и usage.
   Чужой произвольный `taskId` от клиента к адаптеру не передавать.
4. Успех: `download(result['video_url'], managed_path)` в управляемую папку
   файлов проекта; URL берётся из ответа провайдера, путь — из ядра,
   а не из произвольных параметров клиента. Зарегистрировать FileAsset,
   записать `takeFileId`. При ошибке скачивания повторять скачивание,
   не генерацию. Новая генерация создаёт отдельный дубль; выбранный ранее
   дубль не перезаписывать, утверждение — отдельное действие пользователя.

Минимум `project.videoJobs[]`:

| Поле | Значение |
|---|---|
| `id` | ULID задачи в проекте, отличается от внешнего `taskId`. |
| `studio_id` | Студия-владелец записи. |
| `shotId` | Постоянный ID исходного кадра. |
| `taskId` | ID провайдера; `null` до успешного create. |
| `state` | `queued / running / succeeded / failed / cancelled`. |
| `prompt` | Полный текст, который отправлен модели. |
| `sourceVersions` | `{shot: version, scene: version, characters: {id: version}, locations: {id: version}}`. Снимок при запуске. |
| `usd` | Оценка себестоимости запуска; не фактическое списание. |
| `createdAt` | Время создания ядром в UTC. |
| `takeFileId` | ID сохранённого FileAsset, `null` до скачивания. |

Дополнительно сохранять `params` (модель, длительность, разрешение, ratio,
audio, watermark), ссылки на референсы с `fileId`/ролью/версией вместо base64,
`usage`, `error`, `updatedAt`, признак `fake` и ключ повторного запроса.
Изменение исходников не переписывает снимок: ядро отмечает материал как
требующий проверки. Создание, ошибки, смена состояния и утверждение дубля
пишутся в append-only журнал событий.

`usd()` использует установленные в `RAZBOR/15-TOKENY-I-CENY.md` ставки:
480p **$0.103/с**, 720p **$0.231/с**, 1080p **$0.569/с**.
Например, 5 секунд 720p = **$1.155** себестоимости. Наценка 10 %, округление
токенов, резерв и окончательный расчёт принадлежат блоку токенов/ядру;
здесь нет собственного биллинга. Тарифы — проектная оценка из RAZBOR/15,
без заявления о проверенном фактическом списании провайдером.

## Проверка без сети

```sh
cd server
python3 -B -m unittest blocks.video.test_video -v
```

Тесты подменяют `urllib.request.urlopen`, `build_opener().open` и ключи.
Скачивание проверяет HTTPS и при каждом перенаправлении до следующего запроса.
Промпты, ограничения,
HTTP-запросы, состояния, ошибки и скачивание проверяются на подставных
ответах. Платный запуск, доступность ключа/модели и браузерный экран
Production этой проверкой не подтверждаются.
