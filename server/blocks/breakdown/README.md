# Блок разбивки · №21.a

Владелец — Codex, проверяет Claude. Блок принимает схему `tools/razbivka.py`,
валидирует паспорта героев и локаций и строит импорт в переданных коллекциях.
Он не читает файлы, не авторизует запросы и не обращается к другим блокам.

Ядро `server/app.py` передаёт коллекции текущего проекта под блокировкой,
проверяет права, пересматривает связанные кадры/клетки и фиксирует результат
с событиями одной атомарной записью. Ошибки схемы превращаются в HTTP 422.
Контракт — `server/API.md`, HTTP-тесты — `server/test_api.py`.

Вход `POST /api/projects/<slug>/breakdown` — три обязательных массива
`scenes`, `characters`, `locations` из `tools/razbivka.py`, без обёртки `data`.
Схема принимает также `title`, `pages_est`, `caps_mentions` и дополнительные
поля сцен полного результата парсера. Сначала валидируется весь документ:
неверные поля, повторы имён/номеров и ссылки вне импортируемых сцен не
оставляют данных или событий. CRUD `/characters` и `/locations` использует
общую схему `name`, `role`, `identity`, `taboo`, `height`, `refs`, `status`,
`scenes`, `translations`.

Сцены сопоставляются по номеру `n`, паспорта — по нормализованному имени.
Импорт меняет только метаданные разбивки; авторские тексты и замки сохраняются.
Идентификаторы новых сущностей — ULID, `studio_id` задаёт ядро.
Повтор сохраняет ID и заполненные паспорта; отсутствующие записи не удаляются.
Фактически изменённые сущности возвращаются ядру как события, идентичный
повтор даёт только заключительное `breakdown.imported` в `activity`.
В событии импорта хранится объект разбивки по slug проекта и `contentHash`
результата; полная сводка `summary` есть в ответе POST, в ленту она не копируется.
Ядро выдаёт всем новым событиям ULID и `studio_id` проекта. При чтении старого
проекта оно допускает события без `studio_id` и с прежними ID, сохраняет
историю без переписывания и продолжает её хэш-цепочку новыми событиями.

Чтение паспортов требует `overview`, запись — соответственно `heroes` либо
`locations`; импорт требует запись в `breakdown`. Эти права и `If-Match`
проверяет ядро, отдельные права паспортов для импорта не нужны. Такое разделение
оставляет повторную разбивку доступной ответственному за неё без возможности
перезаписать согласованный внешний вид героя или локации.

Проверка из корня репозитория:

```sh
NEYRA_TEST_TRANSPORT=inprocess python3 -m unittest server.test_api
```
