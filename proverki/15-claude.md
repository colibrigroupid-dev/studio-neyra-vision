# Проверка №15 · сервер хранения `server/` · раунд 1

13.10.2026 01:06 · Claude (вне песочницы)

**Что проверял.** `server/app.py`, `server/API.md`, `server/test_api.py`, `server/keys.example.json`, `server/.gitignore`; критерии №15 с доски и раздел «Сценарий и рабочее пространство» в `PROVERKA.md`.

**Чем.** `python3 -m unittest server.test_api` в обычном TCP-режиме (не inprocess): 25 тестов, OK за 13 с. Живой запуск `python3 server/app.py --port 8771` с временным `keys.json` вне репозитория (случайные ключи), запросы curl. Поиск секретов grep. Синтаксис — `ast`.

**Что подтверждено живьём.**
- Без `X-Key` — 401. Писатель без членства в проекте — 403 «Нет доступа к проекту»; после `POST /members` с `keyId` писатель пишет черновик (200), фиксирует версию (201), но в `shots` получает 403 — права проверяет сервер, по разделам.
- Версии: `POST /versions` → v1; правка черновика; `POST /versions/<id>/restore` (с телом `{}`) восстанавливает текст v1 и **сохраняет перезаписанный черновик отдельной версией** (после restore версий две: v1 и автосохранённый черновик) — критерий «восстановление без потери текущего черновика» выполнен.
- Пользовательский ввод экранируется при выдаче: `<b>`, `<script>` возвращаются как `<…>`.
- Хранение: `server/data/<slug>/project.json`, временных файлов после записи не остаётся; `server/data/` в `.gitignore`; статика отдаёт `index.html` (200), `server/data/...` снаружи недоступен (404).
- Пример ключей с пустыми `key` сервер отклоняет (по API.md); секретов в коде нет.

**Находки.**
1. `server/app.py` — `POST …/restore` без тела отвечает 400 «Нужен корректный Content-Length», хотя тело у restore не требуется. Принимать пустой POST (строка в API.md: указать, что тело `{}` обязательно, либо снять требование).
2. `POST /api/projects` с телом `[]` отвечает 422 VALIDATION_ERROR, а не 400 INVALID_JSON, как для битого JSON. Мелочь, но два кода на один класс ошибок — согласовать в API.md.
3. Писателю из `keys.example.json` с `projects: ["demo"]` доступ всё равно закрыт до добавления участником — это задумано (API.md:98–100), но демопроект `studio/` при подключении должен это учитывать: первый шаг любого проекта — `POST /members` для каждой роли.
4. Не проверено: параллельная запись из двух процессов (блокировка заявлена, тестами покрыта, живьём не гонял); поведение при 10 000+ сцен; Windows.
